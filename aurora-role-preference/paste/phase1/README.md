# Phase 1 paste files — for the LIVE app

The live app is **Phase 1 only**. Phase 2 (role alignment) is built and tested in
a separate, unconnected copy.

`../Src/scrLanding.pa.yaml` and `../scrLanding.controls.yaml` are now the
**Phase 2** landing page: three action cards, the third being Role Alignment.
`cardAlign` has **no `Visible` gate** — it always renders, greyed, reading
"NOT YET OPEN". Pasted into the live app it advertises a stage that is not
running, and its formulas reference `varAlign*` variables the Phase 1 OnStart
does not define.

`scrLanding.controls.yaml` in this folder is the **two-card** landing (My
Preference Form + Submissions Overview) as it stood before Phase 2. Use it if the
live app's landing ever needs re-pasting.

| App | OnStart | Landing | Alignment screens |
|---|---|---|---|
| **LIVE (Phase 1)** | `../App_OnStart.phase1.powerfx` | `scrLanding.controls.yaml` *(this folder)* | none |
| **TEST (Phase 2)** | `../App_OnStart.dataverse.powerfx` + `../App_OnStart.alignments-stub.powerfx` until the table exists | `../scrLanding.controls.yaml` | `scrAlignment`, `scrRejection`, `scrAlignLocked` |

Every other screen — scrForm, scrReview, scrQuestions, scrCompleted, scrOverview,
scrSubmissions — is shared, and `../*.controls.yaml` is correct for both.

**Keep this file in step.** It is a frozen copy, not generated by
`tools/gen_paste.py`. If a shared change lands on the landing page (a colour, the
privacy text, the header), it has to be applied here by hand or the live app
falls behind.
